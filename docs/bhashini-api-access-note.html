I am the builder of Bella, a local-first personal voice assistant. I speak Assamese as a first language and use the product daily in Assamese and English.

2. What the product is

Bella is a voice-first personal assistant that runs on the user’s Mac. The user says “Hey Bella” or “Bella”, speaks a request, and Bella replies by voice.

It is meant to do ordinary daily work in the user’s own language, including:

  • conversation and follow-up questions
  • weather, time, and local information
  • calendar, reminders, notes, and email drafts
  • maps and nearby places
  • calls and other device actions the user already permits

Speech is the main interface. Text is secondary. The product only works if it can hear Assamese clearly and speak Assamese clearly. That is why we need Bhashini.

Bella is designed as a personal tool, not a public website that would expose Bhashini keys or resell language APIs.

3. Problem we are solving

A large share of Indian users, including Assamese speakers, do not want to switch to English (or to Hindi/Bengali) to use a voice assistant.

Today, most speech APIs either:

  • do not support Assamese at all, or
  • support Assamese only as a beta / fallback, or
  • treat Assamese as Bengali, which produces the wrong pronunciation and the wrong script behaviour.

We have already built the assistant, the wake word, the tools, and the conversation loop. The missing piece is a reliable, India-built Assamese speech stack:

  1. Speech-to-text (ASR) — so “Bella, আজি বতৰ কেনে?” is understood as Assamese, not as broken English.
  2. Text-to-speech (TTS) — so the reply is spoken in a natural Assamese voice, not a neighbouring language’s voice reading Assamese letters.
  3. Optional translation / transliteration — only when the user mixes English and Assamese, or when a tool result arrives in English and must be spoken in Assamese.

Without this, Assamese users cannot use the product as a first-class voice assistant. That is the gap Bhashini is meant to close.

4. Use case (why we need Bhashini)

Primary use case: real-time Assamese voice conversation with a personal assistant.

Typical turn:

  1. User speaks Assamese (or mixed Assamese–English) after “Hey Bella” / “Bella”.
  2. Bhashini ASR transcribes the utterance in Assamese script.
  3. Bella decides what to do (answer, look up weather, draft a mail, find a place, and so on).
  4. Bhashini TTS speaks a short Assamese reply (usually two to four sentences).

Examples of real requests the product already handles, which we want to run fully in Assamese:

User intent Example (Assamese) Bhashini role
Everyday talk কি খবৰ? আজি ব্যস্ত নেকি? ASR + TTS
Weather / time আজি গুৱাহাটীত বতৰ কেনে? ASR; TTS of the spoken answer
Local search ওচৰত পেট্ৰল পাম্প ক’ত? ASR of the query; TTS of the result

This matches Bhashini’s purpose: digital services in the citizen’s own language, including scheduled and less-resourced languages such as Assamese.

We are not asking for Bhashini in order to build a generic translation website, scrape data, or white-label the API. We need it as the Assamese ears and voice of one assistant product.

5. Why Bhashini specifically

  • Bhashini is the national platform for Indian-language ASR, TTS, and translation.
  • Assamese is an official scheduled language. Support should come from Indian public infrastructure, not from a foreign model that approximates Assamese as Bengali.
  • We need as-IN speech recognition and as-IN speech synthesis as first-class services.
  • Using Bhashini keeps the language layer aligned with Digital India / NLTM rather than depending on a vendor that may withdraw Assamese or keep it in beta.

We already use local models where they work (wake word, English STT, on-device routing). We are requesting Bhashini only for the Indian-language speech path that local English models cannot do well.

7. Expected usage (honest scale)

This is a personal / early-product deployment, not a mass consumer launch.

  • Users at this stage: 1 (developer), then a small private test group
  • Typical load: a few dozen voice turns per day
  • Audio: short commands (a few seconds), not long recordings

8. Data, privacy, and compliance

  • Audio is captured only after the user addresses Bella by name.
  • We will send Bhashini only the utterance needed for that turn (ASR) and the text of the spoken reply (TTS).
  • We will not publish, sell, or sublicense Bhashini outputs or keys.
  • The API key will stay in a private server-side / local environment, not in a public app or web page.
  • We will follow Bhashini’s terms of use, attribution, and any limits on commercial use.
  • No content involving minors, and no use of the API to build a competing language model.

Bhashini access lets us:
